# 薛世奇说物理 · 口播视频剪辑流水线

一套面向物理教学口播视频的本地剪辑工作流。输入一条原始口播，完成转写、校错、粗剪、字幕、标题、图示、音效、封面和发布文案，并生成可直接继续编辑的剪映草稿。

项目的目标不是“把视频剪完”，而是把一期视频的**素材、判断依据、工程文件和交付物**按统一结构保存下来，方便复核、返工和复用。

## 每期交付物

| 交付物 | 内容 |
| --- | --- |
| 剪映草稿 | 1080 × 1920 竖屏工程，视频、图示、标题和字幕可继续编辑 |
| 成片与字幕 | 粗剪底片、最终字幕及必要的中间产物 |
| 发布文案 | 主标题、描述、话题和账号标签 |
| 封面 | 竖版封面和横版封面 |
| 交付说明 | 当期素材状态、产物位置、缺口和操作说明 |

## 流水线

```mermaid
flowchart LR
    A[原始口播] --> B[语音转写]
    B --> C[术语校对]
    C --> D[粗剪与安全校验]
    D --> E[字幕与标题]
    E --> F[图示与音效]
    F --> G[剪映可编辑草稿]
    G --> H[封面与发布文案]
```

核心原则：

- 删除重复表达时，通常保留最后一次完整表达。
- 只修会让学生理解出错的事实和术语，不擅自改写讲者的语言风格。
- 字幕、标题和音量等参数以 [SOP](方法论文档/SOP原版-AI执行版.md) 为准。
- 所有时间点以转写时间戳、静音检测和实际音频能量为依据，不凭听感猜切点。

## 固定目录

以下目录是长期结构。每一期只新增按 `MMDD` 命名的文件或子目录，不改名、不移动固定目录。

```text
.
├─ 原始口播/                 用户放入 MMDD原始口播.mp4
├─ 成片草稿/
│  └─ MMDD成片草稿/          剪映草稿、素材、字幕、中间产物、交付说明
├─ 发布文案/                 MMDD发布文案.md
├─ 封面/                     MMDD封面-竖版.png、MMDD封面-横版.png
├─ 方法论文档/               SOP、剪辑原则、术语表、工具脚本、字体源文件
├─ 参考与数据/               账号作品数据、课标与课本资料
├─ AGENTS.md                 工作区协作约定
├─ 交接说明.md               当前项目状态和交接入口
└─ README.md
```

`MMDD` 必须是四位数字，例如 `0925`。使用 `9.25` 会导致目录和文件排序错乱。

每期草稿目录建议保持如下结构：

```text
成片草稿/MMDD成片草稿/
├─ 剪映草稿/
├─ 素材/
│  ├─ 底片/
│  └─ 图示/
├─ 字幕/
├─ 中间产物/
└─ MMDD交付说明.md
```

## 快速开始

### 1. 获取项目

```powershell
git clone https://github.com/zy20040722-ship-it/XueShiQi.git
cd XueShiQi
```

开始一期视频前，先阅读 [交接说明](交接说明.md) 和 [SOP](方法论文档/SOP原版-AI执行版.md)。

### 2. 放入原始素材

先将原始口播放到当期最终位置，再生成剪映草稿：

```text
原始口播\1106原始口播.mp4
```

剪映草稿使用绝对路径引用素材。素材被引用后不要改名或移动，否则草稿会缺料。

### 3. 检查语音识别环境

```powershell
D:\Software\asr-env\Scripts\python.exe "方法论文档\工具脚本\check_env.py"
```

### 4. 转写口播

```powershell
powershell -ExecutionPolicy Bypass `
  -File "方法论文档\工具脚本\run_transcribe.ps1" `
  "原始口播"
```

可为单个视频、整个目录或指定输出目录执行；无 NVIDIA GPU 时增加 `-Cpu`。

### 5. 按 SOP 完成剪辑

依次完成转写校对、粗剪、字幕、标题、图示和音频处理，最后生成并安装剪映草稿。当前脚本记录了上一期的实际路径，新一期运行前应先核对脚本顶部的路径常量。

安装草稿后，在剪映中按以下路径打开：

```text
剪映首页 →「本地草稿」→ 点击当期草稿卡片
```

## 环境依赖

- Windows 10/11
- 剪映专业版
- Python 3，默认虚拟环境为 `D:\Software\asr-env`
- Node.js
- FFmpeg 8.x
- faster-whisper、CTranslate2、FFmpeg 相关 Python 与 Node 依赖
- NVIDIA GPU 为推荐配置；转写脚本支持 CPU 模式
- 金陵体和丽金黑字体文件

完整安装位置、模型说明和已知问题见 [环境与工具说明](方法论文档/环境与工具说明.md)。

## 素材与版本管理

Git 仓库只保存文档、脚本、数据和轻量图片。以下内容不会提交到 GitHub：

- 原始视频、切片、音频和录屏
- 字体文件
- 安装包、压缩包、缓存和日志
- 本地环境变量与密钥

这样可以避免仓库被数 GB 的视频撑大。大体积素材仍需在本地或独立的存储介质中备份。

## 使用边界

- 自动转写和自动剪辑负责提高效率，最终判断仍以内容正确、表达自然和画面可读为准。
- 剪映草稿中的素材路径是绝对路径，换电脑或移动目录后需要重新配置。
- 公开发布前应检查字幕中的物理术语、数字、单位和事实表述。
- 封面和文案应延续讲者的表达风格，不把口语内容改成模板化书面语。
