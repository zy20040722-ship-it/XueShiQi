# 环境与工具说明

> 记录时间：2026-09-28
> 这里是「薛世奇说物理」视频剪辑流水线用到的全部工具。换电脑或重装时按本文重建即可。

## 一、安装位置总表

| 工具 | 位置 | 说明 |
|---|---|---|
| FFmpeg 8.1.3 | `D:\Software\ffmpeg\bin` | 音视频处理核心，已加入用户 PATH |
| Python 虚拟环境 | `D:\Software\asr-env` | 语音识别专用，约 1.5 GB |
| 模型缓存 | `D:\Software\asr-models` | 语音识别模型，约 1.5 GB |

## 二、语音识别方案

**主力：faster-whisper + large-v3-turbo（CTranslate2 格式）**

- 模型位置：`D:\Software\asr-models\ct2\large-v3-turbo`
- 来源：ModelScope 的 `pengzhendong/faster-whisper-large-v3-turbo`
- 实测速度：**60 秒音频 8.6 秒转完**（RTX 4060，float16）
- 输出词级时间戳，精确到 0.01 秒

**备用：FunASR**（中文原生，用于交叉核对疑难段落）

**辅助：物理术语热词表** —— `流水线文档\物理术语表.txt`，252 条，从苏科版八上八下课本提取

**辅助：术语纠错表** —— `流水线文档\术语纠错表.txt`，识别后再做一次文本替换，兜住热词没纠正过来的错字

## 三、日常使用

转写一个视频或整个文件夹：

```
powershell -ExecutionPolicy Bypass -File tools\run_transcribe.ps1 "素材文件夹路径"
```

输出结构（每个视频一个文件夹）：

| 文件 | 内容 |
|---|---|
| `transcript.json` | 逐句 + 逐词时间戳、置信度（粗剪的关键数据） |
| `transcript.txt` | 纯文字稿 |
| `transcript.srt` | 字幕文件 |
| `silences.json` | 所有停顿段（静音超 0.35 秒），直接对应可剪掉的位置 |

## 三之二、转写质量的关键参数（踩坑记录）

| 问题 | 现象 | 解决办法 |
|---|---|---|
| 术语听错 | "受力分析" 听成 "收力分析" | 热词表。但中文按字节分词，热词超过约 150 字会报 `maximum decoding length must be > 0`，故取前 120 字 |
| 重复幻觉 | 30 秒后开始输出"老板老板老板…" | `condition_on_previous_text=False` + `repetition_penalty=1.08` + `no_repeat_ngram_size=3` |
| 同音字 | "下限" 听成 "下线" | 纠错表正则替换，可带上下文（如 `课标是下线 => 课标是下限`） |
| **词级时间戳偏后** | 一个字的时间戳能拉长到 1.1 秒，尾巴拖进后面的静音里 | **不能用它判断该从哪切**。判断切点要用 ffmpeg 的 `silencedetect`，或用 PCM 实测能量。实测：被误判"切到词"的位置电平是 -60 dB，而正常说话是 -29 dB |
| 控制台编码 | 打印生僻字时整个流程崩掉 | 脚本开头把 stdout/stderr 重设为 utf-8 |

## 四、已知的坑（都踩过了）

1. **系统代理**：机器上配了 `127.0.0.1:7890` 的代理，代理没开时 pip 会卡死。所有脚本都设了 `NO_PROXY=*` 直连。
2. **HuggingFace 国内镜像极慢**：hf-mirror.com 只有 50 KB/s，不要用。模型一律走 ModelScope，约 1 MB/s。
3. **PyTorch CUDA 版不必装**：faster-whisper 用 CTranslate2 推理，只需要 `nvidia-cublas-cu12` 和 `nvidia-cudnn-cu12` 两个运行库（清华源 12～14 MB/s）。
4. **抖音网页版只暴露部分作品**：账号标注 30 条，网页端只给出 19 条，其余需要登录作者后台。
